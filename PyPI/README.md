# tiny-text-stats

`tiny-text-stats` — это маленькая учебная библиотека для подсчета простых
характеристик текста. Я выбрал такую идею, потому что ее легко проверить: функция
получает строку и возвращает количество символов, слов и строк.

Проект сделан как отдельное задание в монорепозитории FOSSDEV. Он не зависит от
прошлых веток с диаграммами и Make-заданием.

## Ссылки

- Репозиторий GitHub: <https://github.com/xx663xx/repo>
- TestPyPI: <https://test.pypi.org/project/tiny-text-stats-2026/>

Пакет публикуется только на TestPyPI. В основной PyPI его загружать не нужно.

## Что делает библиотека

В пакете есть функция `analyze_text`. Она возвращает объект `TextStats` с тремя
полями:

- `characters` — количество символов;
- `words` — количество слов;
- `lines` — количество строк.

Пример использования:

```python
from tiny_text_stats import analyze_text

stats = analyze_text("hello world\nagain")
print(stats.words)
```

`setup.py` хранит описание пакета: имя, версию, автора, ссылку на GitHub,
зависимости и настройки поиска модулей в папке `src`. `pyproject.toml` нужен,
чтобы сборщик понимал, какие инструменты использовать.

## Проверка через Make

Все основные действия вынесены в `Makefile`, чтобы не запускать команды вручную
в разном порядке.

```bash
make install
make lint
make type
make test
make docs
make build
```

Есть общий таргет:

```bash
make check
```

Он запускает проверку стиля, типов, тесты, сборку простой документации и сборку
пакета.

## Установка из TestPyPI

После публикации пакет ставится командой:

```bash
pip install --index-url https://test.pypi.org/simple/ tiny-text-stats-2026
```

Для публикации используется отдельный таргет:

```bash
make publish-testpypi
```

Перед ним нужно иметь токен TestPyPI. Команда использует `twine` и репозиторий
`testpypi`, поэтому случайно отправить пакет в основной PyPI не должно получиться.

## Почему это сделано именно так

Задание просит показать не просто код, а воспроизводимую упаковку проекта.
Поэтому здесь есть отдельная папка `src`, тесты, описание сборки и автоматизация
через Make. Логика простая: сначала проект ставится в локальное виртуальное
окружение, потом проходят проверки, после этого собирается архив для публикации.
